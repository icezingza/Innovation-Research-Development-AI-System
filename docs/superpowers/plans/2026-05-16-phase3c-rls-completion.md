## ข้อควรระวัง

1. **Policy name ซ้ำกันได้** — แต่ละตารางมี scope ของตัวเอง ใช้ชื่อ `tenant_isolation` ซ้ำกันในแต่ละตารางได้
2. **`IF NOT EXISTS` ไม่รองรับใน `CREATE POLICY`** — ถ้ารัน upgrade ซ้ำจะ error — Alembic จัดการ idempotency ผ่าน version table อยู่แล้ว
3. **`FORCE ROW LEVEL SECURITY`** — ยังไม่จำเป็นในขั้นนี้ (เปิดไว้สำหรับ superuser ในภายหลัง)
4. **`get_rls_db` dependency** ใน `src/security/rls.py` ต้องถูก inject ก่อนทุก route ที่ query ตารางเหล่านี้ — ตรวจสอบใน Phase ถัดไป
